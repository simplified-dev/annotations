name: annotation-surface
description: Per-annotation reference for the simplified-annotations library - what each of the seventeen annotations emits, its attributes, its legal targets, and the failure-mode argument behind each default. Use when adding, changing, or debugging any annotation in dev.simplified.annotations.
---

### Annotations (`dev.simplified.annotations`)
- `ResourcePath.java` â€” `@Retention(CLASS)` annotation targeting fields, parameters, and methods. Has an optional `base` attribute that prefixes the resolved path.
- `XContract.java` â€” `@Retention(CLASS)` annotation targeting methods and constructors. Attributes: `value` (semicolon-separated clauses), `pure`, `mutates` (comma-separated `this`/`io`/`paramN`). Full grammar is on the annotation's Javadoc.
- `ClassBuilder.java` â€” `@Retention(CLASS)` annotation targeting types/constructors/methods. Drives the builder processor. Full Lombok `@Builder` parity (`style`, `setters`, `builder`, `access`, `constructorAccess`, `validate`, `emitContracts`, `emitGenerated`, `factoryMethod`, `exclude`, `retainInit`, `generateImpl`, `generateCopyConstructor`). `constructorAccess` sets the visibility of the synthesised all-args ctor and defaults to package-private, matching Lombok; `access` governs the builder class and bootstrap methods and stays `PUBLIC`.
- `Getter.java` / `Setter.java` â€” `@Retention(CLASS)`, `@Target({TYPE, FIELD})`. Synthesise read and write accessors. Attributes: `value` (an `AccessLevel`), `style`, `name` (a `NamePattern`), `exclude` (type level only), `emitContracts`, `emitGenerated`. A field-level annotation beats the enclosing type's, and `AccessLevel.NONE` on a field is how one field opts out of a type-level fan-out. **Both default to `style = SIMPLIFIED`, which mints bean-shaped accessors** - a bare `@Getter` has to keep producing `getX()`/`isX()` or every existing call site is renamed. Records and interfaces are rejected; classes and enums are supported, and enums are the first `ElementKind` any mutator in this project has touched. Emission lives in `dev.simplified.accessor.mutate.AccessorMutator`, dispatched from `ClassBuilderProcessor` rather than a processor of its own **so ordering against `@Lazy` is a guarantee** - processor order within a round is unspecified, and a `@Getter` racing `@Lazy` emits a duplicate `getX()`.
- `UtilityClass.java` â€” `@Retention(CLASS)`, `@Target(TYPE)`. Marks the class `final` and retrofits the constructor javac already generated into one that throws. Attributes: `makeFinal`, `members` (`REQUIRE_STATIC` default / `MAKE_STATIC`), `nestedTypes`, `constructorAccess`, `message`, `emitContracts`, `emitGenerated`. **Deliberately splits Lombok's feature in two**: the `final`-plus-constructor half is on by default, and the implicit-`static`-on-members half - the source of every sharp edge, and the half that changes the meaning of a declaration the author wrote - is opt-in behind `members = MAKE_STATIC`. The default instead reports an instance member as an error. Lives in `dev.simplified.utility.{apt,mutate}` with its own processor, since it has no ordering relationship with anything. `isLegalTarget` also rejects a target carrying `@ClassBuilder`: one annotation exists to produce instances and the other to forbid them, and without the rejection the pair compiles into a builder whose `build()` calls a constructor that throws - a runtime failure in place of a diagnostic.
- `Log.java` â€” `@Retention(CLASS)`, `@Target(TYPE)`. Injects one `private static final org.apache.logging.log4j.Logger log = LogManager.getLogger(Foo.class)`, which is byte-for-byte what Lombok's `@Log4j2` emits. Attributes: `topic` (written, the factory takes the string literal instead of the class literal - Lombok's rule), `name` (the field name, resolved through `NamePattern` with the placeholder optional, `""` inheriting the literal `log`), `emitGenerated`. **Single backend by decision**: `@Log` means log4j2, with no `LogBackend` enum and no `value()`, because a second backend can be added later as `LogBackend value() default LOG4J2` - an annotation member with a default is source- and binary-compatible, so every bare `@Log` keeps meaning exactly what it means today. log4j2 is named only as FQN strings through `JavacTypeFactory.qualIdent(String)`, keeping `:library`'s classpath at zero dependencies. The field is always `private static final`, and that is what makes the feature self-contained: the builder's static filter already skips it, so there is no ordering relationship with `@Lazy` or `@ClassBuilder` and `dev.simplified.log.apt.LogProcessor` is its own processor rather than a dispatch from `ClassBuilderProcessor`. The class literal is minted **raw** - `MutationContext.targetType()` re-applies the target's type arguments and would yield the uncompilable `Foo<T>.class`. Legal targets are classes and enums; interfaces, records and annotation types are errors. A field of the resolved name already declared on the target is a warn-and-skip, and an inherited one is deliberately not a collision - Lombok's field is `private`, so a super's `log` is invisible and the synthetic field is still correct.
  - **The one dependency the consumer must supply is checked before anything is emitted.** `@Log` is the project's only generator whose output names a third-party API, so a module without log4j2 is the ordinary failure rather than an exotic one - and it is the failure the AST path reports worst, since the injected field has no source line and javac's `cannot find symbol` lands on a declaration the author cannot open. `LogProcessor` resolves `org.apache.logging.log4j.Logger` through `Elements.getTypeElement` first and reports an ERROR on the annotation naming `org.apache.logging.log4j:log4j-api`, and `LogInspection` mirrors it. This is a validation read, not the classpath *probing* that ruled out inferring a backend: nothing about the output depends on the answer, only the message. The augment provider still contributes the unresolved type rather than falling back to `Object`, so the editor keeps saying exactly what javac says.
- `SilentThrows.java` â€” `@Retention(CLASS)`, `@Target({METHOD, CONSTRUCTOR})`, `Class<? extends Throwable>[] value() default Throwable.class`. Wraps the body in `try { â€¦ } catch (Throwable $t) { throw $silentThrow($t); }` so a checked exception leaves a method that declares none. **The rethrow helper is emitted, not shipped**: a `private static <T extends Throwable> RuntimeException $silentThrow(Throwable) throws T` injected once per declaring class, rather than a runtime type in the library. A second mandatory runtime dependency for a feature that holds no state moves the library the wrong way - `Lazy<T>` is not a counter-example, it has to exist at runtime because it *holds* the memoized value. Three details are load-bearing: the **explicit `<RuntimeException>` type witness** is emitted rather than inferred, so the result does not depend on JLS 18.1.3's unbound-`throws`-variable rule behaving identically across JDK 17 to 25; `@SuppressWarnings("unchecked")` on the helper is not optional, since consumer builds run `-Werror`; and the existing `JCBlock` is **reused** as the try body rather than copied, so there is no re-attribution and no position reset.
  - **The constructor prologue is split off and re-prepended outside the try.** No `try` may enclose an explicit `this(...)` / `super(...)`. `TreeInfo.isSelfCall` was the obvious tool and **does not exist in javac 25** - it is replaced by a local structural test, and the search runs over the whole prologue rather than only `body.stats.head`, because Java 25's flexible constructor bodies allow statements before the explicit invocation. Head-only was correct through 21 and would have mis-wrapped silently on 25.
- `Cleanup.java` â€” `@Retention(SOURCE)`, `@Target(LOCAL_VARIABLE)`, no attributes. Splits the enclosing block at the annotated declaration and wraps the remainder in `try (name) { â€¦ }`. **The single `JCIdent` resource is the whole trick**: it produces exactly the tree javac's parser builds for the existing-variable form, so javac's own `Lower` generates the close, the null skip and the `addSuppressed` bookkeeping. The result is not equivalent to try-with-resources, it *is* try-with-resources - which also means a close failure is **suppressed rather than masking** the primary exception, the one place this deliberately improves on Lombok. `value()` is not carried over: every workspace site is bare, and the named-method fallback would have shipped Lombok's masking wart untested.
  - **The empty tail is wrapped like any other.** A declaration as its block's last statement gives an empty try body, which is legal - and it is exactly the case a `tail.isEmpty()` shortcut skips, leaving the resource **never closed**, silently, past any test that only checks that the file compiled.
  - **Discovery cannot use the Element model at all.** javac computes a round's annotations-present set with an `ElementScanner` over root elements, and a local variable is not an enclosed element of anything - `ExecutableElement.getEnclosedElements()` returns parameters and nothing else. A processor declaring the FQN would never be invoked. Hence `CleanupProcessor` claims `@SupportedAnnotationTypes("*")` and walks the trees itself. Widening the shared processor instead was rejected: a consumer using only `@ClassBuilder` must see no trigger change.
- `EqualsAndHashCode.java` â€” `@Retention(CLASS)`, `@Target(TYPE)`. Injects the pair over the target's instance state. Attributes: `identity` (a nested `Identity`), `callSuper`, `of`, `exclude`, `cacheHashCode`, `useAccessors`, `emitContracts`, `emitGenerated`. **Records are the shape it exists for and the shape Lombok refuses**: `JavacHandlerUtil.isClass` excludes `RECORD`, so every record whose implicit `equals` compares an array component by reference has had to hand-write the pair. Injection works because JLS 8.10.3 synthesises the implicit pair only when the body does not declare it, so a `JCMethodDecl` appended during a processing round is the pair that survives - proved on 17, 21 and 25 by `RecordEqualsInjectionSpike` before any of this was written. Enums are rejected instead: `Enum.equals` is `final` and identity-based already.
  - **`identity` defaults to `EXACT_CLASS`, and the argument is about failure modes rather than taste.** `getClass()` comparison is always a valid equivalence relation and needs no cooperation from any other class, so it is right everywhere the other two are and right in the two places they are not; its cost is a *narrow* answer, where both alternatives can produce a silently *wrong* one. Bare `INSTANCE_OF` is asymmetric the moment a subclass adds a value component. `INSTANCE_OF_CANEQUAL` fixes that but is a cooperation protocol rather than a defence, and adds a failure `EXACT_CLASS` does not have: two subclasses of an annotated base that neither override compare **equal to each other**. All three ship because the workspace needs all three - one live site hand-writes the bare relation deliberately so a materialised and a borrowed backend compare equal, and a JPA `@IdClass` wants the hook.
  - **`callSuper` defaults to `AUTO`, resolved annotation-mirror-first.** Deciding it by scanning members of types in the same round is order-dependent - the round's annotated elements arrive as an unordered set, so a superclass processed after its subclass has not been mutated yet and the answer changes between builds with nothing to see. The member scan requires **both** `equals` and `hashCode`; finding exactly one is an ERROR, because a superclass overriding `equals` alone yields value equality over an identity hash. The resolution is reported as a `NOTE` **only when there is a superclass**: `AUTO` can flip from `NO` to `YES` when a superclass in another artifact gains the annotation, and a direct subclass of `Object` can never flip, so noting it there would put a message on nearly every annotated type.
  - **`useAccessors` defaults to `false`, inverting Lombok, and `true` gets its own resolver.** Reusing the builder's `from(T)` seeding ladder would be a silent `hashCode` break: that ladder matches on **name only**, with no return-type or owner check. `dev.simplified.accessor.apt.AccessorReads` instead takes names from `AccessorScheme`, skips a field carrying `@Getter(AccessLevel.NONE)`, and accepts only a target-declared zero-arg accessor whose return type is assignable to the member's. Consequently the emission row is chosen from the **read expression's** type, not the declared field's - a `List` field read through an `int[]`-returning accessor would otherwise dispatch to `Objects.equals` and compare by identity.
    - **It reads the tree as well as the element model, and the acceptance rule on each side is different on purpose.** An accessor `@Getter` synthesises lands in `JCClassDecl.defs` and never in `ClassSymbol.members_field`, so a model-only scan can never see one and `@Getter` + `useAccessors` silently degraded to a field read with a `NOTE` - the opposite of what the attribute says, and a contradiction of the pass ordering that exists to make it true. The tree side cannot type-check: `restype` there is an unattributed `JCExpression` and `Types.isAssignable` does not apply to it. So it matches on **authorship instead of on type**, and specifically on `AstMarkers.isPassMarked(method, AccessorMutator.PASS)` rather than on `isGenerated`. That narrowing is load-bearing: `readCandidates` ends with the bare field name, so a field named `mutate` or `hashCode` matches the builder's `mutate()` or the equality pass's `hashCode()` under the broader test, and the result is an `equals` that reads the wrong member and compares two identical objects unequal, from a clean build. Taking `member.type()` as the read type is exact only because `AccessorMutator` mints the return type from `element.asType()` on the very field the body returns - a claim about that one pass and no other.
  - **`hashCode` is a `result * PRIME + term` accumulator, not `Objects.hash(...)`, for correctness rather than allocation.** `Objects.hash` takes `Object...`, so an array argument hashes by identity and any type with an array member gets a hash inconsistent with the `equals` beside it. `cacheHashCode` adds a `private transient int $hashCode` memo with three load-bearing details: `transient`, since a persisted hash is meaningless across JVMs; a computed `0` normalised to `Integer.MIN_VALUE`, since `0` is the field's own default and therefore the not-yet-computed sentinel; and **no `volatile`** - the race is benign, two threads compute the same value and a 32-bit `int` write cannot tear.
  - **The memo is refused on a record, and the refusal is a choice rather than a limitation.** `RecordFieldInjectionSpike` proves an injected instance field compiles and works on 17, 21 and 25. It is refused because nothing measured needs it and because the mechanism steps around a deliberate language rule rather than using a sanctioned seam - the asymmetry with the method injection, which JLS 8.10.3 explicitly leaves open, is the whole distinction.
  - **A target already declaring either member is an ERROR naming both**, not the silent skip `@ClassBuilder` and `@Getter` perform. Those decline to supply a member the author can still see and call; an annotation asking for an equality relation that then supplies none leaves the type with a relation nobody wrote down. A supertype declaring either `final` is an ERROR naming the supertype, since no override can compile past it.
- `ToString.java` â€” `@Retention(CLASS)`, `@Target(TYPE)`. Attributes: `callSuper`, `includeFieldNames`, `style` (a nested `Style`, `SIMPLIFIED` default), `of`, `exclude`, `useAccessors`, `emitContracts`, `emitGenerated`. Mirrors `@EqualsAndHashCode` in member selection and in four attributes, deliberately: they share one selection component, and a type whose `equals` counts an inherited field while its `toString` hides one reads as a bug in whichever member is looked at second. **The one sanctioned divergence is `transient`, which `@ToString` keeps and `@EqualsAndHashCode` drops** - a field excluded from serialization is by definition not part of the value but is still state a debugger dump wants. The format is `Name[a=1, b=2]`, which is what `java.lang.Record` and `InterfaceImplEmitter` already print, so one library does not ship two shapes; `style = LOMBOK` is offered and not defaulted, because on Maven Central a consumer can grow a parser for the output even though none exists today. **An already-declared `toString` is left alone with a `NOTE` rather than reported**, the deliberate asymmetry with the equality pair: a collection's behaviour depends on that pair, and nothing depends on this member.
- `CallSuper.java` â€” top-level `public enum {AUTO, YES, NO}`, shared by both, on the cardinality rule the package already follows: an enum read by more than one annotation is top-level (`AccessLevel`, `NamingStyle`), one read by exactly one is nested (`UtilityClass.Members`, and so `Identity` and `Style`).
- `EqualsExclude.java` / `EqualsInclude.java` / `ToStringExclude.java` / `ToStringInclude.java` â€” `@Retention(CLASS)`, `@Target({FIELD, METHOD})` markers. The include form overrides the `transient` skip and admits a zero-arg non-`void` method as a term. **`@ToStringInclude` carries `name` and `rank` and `@EqualsInclude` deliberately carries neither**: rank changes print order, which is cosmetic and visible in the output, where the same attribute on the equality pair would make an emitted **hash** depend on an ordering rule nothing in the source shows.
- `NamingStyle.java` / `SetterNames.java` / `BuilderNames.java` â€” the naming surface, replacing the retired `methodPrefix` and the five flat `*Name` attributes in 2.5.0. **The split is by cardinality, not by "field vs class"**: `@SetterNames` names the six roles generated *once per field* (`set`, `flag`, `add`, `put`, `compute`, `clear`), `@BuilderNames` names the five members generated *exactly once* (`type`, `builder`, `build`, `from`, `toBuilder`). That difference is the whole reason for two annotations - a per-field name **must** carry the `{}` placeholder or every field collides, while a once-per-target name defaults to a plain literal. `style` sets both halves; a written name always wins.
  - `{}` expands to the field name, `@Negate` stem, or `@Collector` singular for setters, and to the target's simple name for builder names (undocumented there deliberately - it works, but the alternatives to allowing it were worse and nobody should use it). Capitalised unless it opens the pattern.
  - `NONE` (`"-"`, not a legal identifier) suppresses; `INHERIT` (`""`) takes the style's. Four members refuse suppression: `set`, `type`, `build` in the annotations, enforced by the processor and the inspection.
  - **The boolean special case is gone**: the typed setter is the ordinary `set` role (`animated(boolean)`), and the zero-arg convenience is the separate `flag` role (`isAnimated()`). Before 2.5.0 both were hardcoded `is`-prefixed and unreachable by any attribute.
  - **`generateBuilder` / `generateFrom` / `generateMutate` retired with them.** Each duplicated its name attribute - four emission sites read `generateX() && !nameX().isEmpty()`. `BuilderScheme` resolves a `NONE` to the empty string, so emptiness is now the single opt-out signal. `generateImpl` and `generateCopyConstructor` stay: they switch synthesis strategy rather than suppressing a named member.
- `BuilderDefault.java` â€” `@Retention(CLASS)`, `@Target(FIELD)`. `boolean value() default true`. Overrides the class-level `@ClassBuilder(retainInit)` policy for one field: bare form retains the declared initializer, `@BuilderDefault(false)` opts out. A field with neither inherits the class setting.
- `BuilderIgnore.java` â€” `@Retention(CLASS)`, `@Target(FIELD)`. Marker; excludes the field from builder synthesis. Field-local alternative to `@ClassBuilder(exclude = ...)`.
- `BuildFlag.java` â€” `@Retention(RUNTIME)`, `@Target({FIELD, METHOD})`. Runtime validation (nonNull/notEmpty/group/pattern/limit). The only field companion needing RUNTIME retention, since `BuildFlagValidator` reflects it inside the generated `build()`. **`METHOD` exists solely for interface targets**, which declare no fields to carry a constraint: `FieldSpec.fromInterfaceAccessor` keeps the raw mirror and `InterfaceImplEmitter` copies it onto the `<Name>Impl` field, which is what the validator actually reads. Emission needed no change - `build()` already validated the constructed instance, whose runtime class is the `Impl`. It is the one companion whose `@Target` is wider than the place it takes effect, so the IDE inspection warns on a `@BuildFlag` written on any other method.
- `ObtainVia.java` â€” `@Retention(CLASS)`, `@Target(FIELD)`. Redirects how `from(T)` / `mutate()` read the field, overriding the default seeding ladder (below).
- `Generated.java` â€” `@Retention(CLASS)`, `@Target({TYPE, CONSTRUCTOR, METHOD, FIELD})`, no attributes. Marks every member the pipeline synthesises so coverage tools skip them. **Two properties are load bearing and neither is style**: the simple name must stay `Generated` because JaCoCo matches on it, and retention must stay `CLASS` - `SOURCE` never reaches a class file and an AST-injected member has no source to read instead. Gated by `@ClassBuilder(emitGenerated)`, default `true`, independent of `emitContracts`. It lands on synthesised members and synthesised types, **never on the annotated target** - marking the target would discard coverage for the author's own methods. Attachment is centralised in `AstMarkers.markGenerated(node, GeneratedAnnotations)` rather than at each `make.Modifiers(..)` site, which makes the invariant structural: a node the pipeline marks is a node whose class file carries the marker. The one-arg `markGenerated(node)` overload survives for nodes that cannot hold an annotation (a static initialiser block) and for `LazyFieldMutator`'s in-place rewrite of the author's own field declaration, which is marked for collision detection but must not be claimed as generated.

These four replaced a single `@BuildRule` parent in 2.5.0. Bundling them forced `RUNTIME` retention on all four to serve `flag` alone; splitting confines it to `@BuildFlag` and makes the field-level surface uniform with `@Collector` / `@Negate` / `@Formattable` / `@Lazy` / `@KeyField`.
- `Collector.java`, `Negate.java`, `Formattable.java` â€” field-level `@Retention(CLASS)` type-specific companions (collection/map, boolean, String).
- `AllArgsConstructor.java` / `RequiredArgsConstructor.java` / `NoArgsConstructor.java` / `BuilderArgsConstructor.java` â€” `@Retention(CLASS)`, `@Target(TYPE)`, one `access` attribute each plus `emitGenerated` (`@NoArgsConstructor` adds `force`). One field-selection policy with four settings, which is how Lombok models the same feature and why one mutator serves them. `staticName`, `onConstructor_` and `AccessLevel.NONE` are not carried over - zero sites each, and `NONE` on an annotation whose only job is to generate a member leaves it with nothing to do, so it is an error.
  - **"Required" means `final` without an initializer**, not "final". An initialized final is already definitely assigned, so adding one initializer shortens the constructor - which is why the resolved signature is rendered in the gutter rather than just the annotation name. A nullness annotation on a mutable field is deliberately **not** read as required: nullness says what a field may hold, not whether the constructor must be told.
  - **These annotations ADD a constructor, they do not back off.** `@ClassBuilder` declines to synthesise when the author wrote one; copying that guard here would silently do nothing on every constant-carrying enum, which declares a constructor by necessity. A duplicate erasure between two of them is reported here, naming both, rather than reaching javac as a duplicate constructor on a line the author cannot see.
  - **`transient` fields are parameters.** `collectFields` drops them for the builder, having no use for a field it must not persist; reusing that view would quietly shorten the constructor of every type a reflective framework populates, and the next same-typed argument then binds to the wrong slot with nothing failing.
  - **`@Lazy` fields are not.** The field owns a `Lazy<T>` wrapper it installs itself and the same rewrite makes it `final`, so a plain parameter assigns it twice. Only the builder's constructor knows how to hand it a supplier. The omission is reported as a `NOTE`, since a silently shortened "all args" is exactly what has to be said out loud.
  - **Enums are the first `JCClassDecl` of kind `ENUM` the constructor pipeline touches.** The constant list binds positionally to the generated arity, an enum's constants are themselves `JCVariableDecl`s of the enum type (filtered on `ENUM_CONSTANT` rather than trusting the `static` test), and the constructor is forced `private` whatever `access` says - a written `access = PRIVATE` there is a common no-op that has to be accepted.
  - **No `removeDef` was needed**, which is the phase's one real surprise. `@NoArgsConstructor` has to end up with the `private` constructor javac already generated as `public`, and the pipeline had never deleted a member. It does not have to: appending any constructor makes javac drop the default it generated, so the replacement happens by re-entry between rounds. Verified across eight target shapes before anything else was written, and pinned by a test that asserts exactly one constructor survives.
- `AccessLevel.java` â€” enum with `emits()` and `toKeyword()`. Gained a `NONE` constant for the accessor annotations. `NONE` is the absence of a member rather than an access level, so `toKeyword()` **throws** on it: the empty string already means `PACKAGE`, and mapping `NONE` there would quietly emit a package-private member where the author asked for none. Callers gate on `emits()`. Adding it broke two exhaustive switches (`toKeyword`, `MutationContext.accessFlagFor`) and one string switch that silently defaulted to public (`LazyFieldMutator.accessFlagFor`, which now reports `@Lazy(access = NONE)` as an error - a `@Lazy` field's storage is `Lazy<T>`, so suppressing its getter leaves the field unreadable).

  The naming trio is a quartet: `AccessorScheme` joins `SetterScheme` and `BuilderScheme` in `classbuilder.apt`, resolving the three per-field accessor patterns `NamingStyle` now carries (`accessorGet` / `accessorIs` / `accessorSet`, prefixed to stay clear of the builder's own `set()` role). `NamingStyle` gained a `FLUENT` constant - `{}` for all three - which is what replaces Lombok's `@Accessors(fluent = true)`; **no `@Accessors` clone ships**, because every one of the workspace's ~196 sites is that single form and the existing `NamePattern` grammar already expresses it. The shared bean-accessor triple lives in a nested `Shared` holder class rather than a `static final` field, because an enum constant's argument list cannot read a static field of its own enum.
