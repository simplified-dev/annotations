Flags misuse of the @Lazy field annotation:
  • @Lazy must apply to an instance field - static fields and record components have no place to install the deferred backing storage.
  • @Lazy does not apply to an array field - the storage rewrite has no shape for one.
  • @Lazy on a class without @ClassBuilder requires either a field initializer or a constructor assignment - whichever is written becomes the supplier body. With neither, and with no builder driving construction, no value can ever be produced.
  • @Lazy alongside @Collector, @Negate, @Formattable, @BuildFlag, or @ObtainVia is not supported - the companion-annotation contracts assume direct T-typed storage rather than a deferred supplier. @BuilderDefault and @BuilderIgnore are not flagged: they govern how the builder treats the field, not how it is stored.
  • @Lazy(name) written without the {} placeholder - the pattern is applied to one field's name, so a literal names the getter the same thing whatever the field is called.
  • A lazy getter spelled differently from the accessors a type-level @Getter asks for. @Lazy names its own getter and the accessor pass steps over a lazy field, so a class that spells its accessors one way can end up with a single field spelled the other and nothing else to say so. Reported only when @Lazy names neither style nor name: writing one is a choice about that field rather than a slip.
  • @Lazy alongside Lombok @Getter is redundant: @Lazy generates its own memoizing getter, so Lombok's getter is never emitted.

Hard errors (static, record component, array, nothing to defer, an unexpandable name pattern) report at ERROR severity because the AST mutation cannot complete safely. Companion clashes report at ERROR; the naming mismatch and Lombok redundancy report as weak warnings, both being about a member that is generated either way.

Primitive fields are supported and are not flagged: the memoized value keeps a primitive slot and only the supplier's type argument is boxed.
