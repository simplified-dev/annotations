Reports a builder declared beside @ClassBuilder whose shape cannot carry the generated members.

The processor refuses these with a compile error, and until this fires the editor had no analogue: the whole generated surface appeared in completion on a class the build was going to reject, so the first sign of the problem was a failure inside code the author never wrote.

The shapes refused, each for a reason the generated members cannot work around:

  • A record, an enum or an interface - a record takes no instance field, an enum no new and an interface neither, so only a class can hold the slot fields and the constructor the entry points call.
  • Not static - an inner class captures the enclosing instance, so the static entry point has nothing to create one from.
  • abstract where the entry points instantiate it - the builder a standalone target or a concrete link declares is what builder() calls new on.
  • The wrong type parameters - the generated members are written in the builder's own re-declared parameters, so they have to be present and in the same order for a setter to name a slot's type at all.
  • Other bounds on them - the generated members apply the builder's parameters to the target and the target's to the builder, so each re-declared parameter carries the bounds the target writes on it, compared by simple name in any order; a looser bound fails the generated build() and a narrower one the generated builder().
  • An unbounded or otherwise bounded trailing pair on a self-typed builder - every link binds the pair to itself and its own builder, so each type the first parameter's bound names has to be the target, a type the target's own extends or implements clause names, or Object, and the second has to be bounded by the builder applied to the pair in order. A type the target reaches only through a supertype further up is refused, the names being unable to tell it from an unrelated one.
  • The wrong extends clause - a chained builder inherits the parent's setters through it, so it has to name the annotated ancestor's builder, qualifier included, and pass it the ancestor's own arguments followed by the link and its builder, or on an abstract builder its own trailing pair.
  • A build method returning something else, on a chain only - the method a link inherits has to be the one its role declares, or on a root the root itself, which every link's build method overrides. Standing alone nothing generated calls build(), so an author's own is kept whatever it returns.

A target in a SuperBuilder chain merges into its declared builder as well, so a root, a concrete link and a chained abstract are each judged against the shape their role generates. A root or chained abstract's builder whose constructors all take parameters, or whose self() - declared, or on a root inherited from a supertype - is final, is reported on its name, since every link below calls the one and overrides the other. So is a root's builder inheriting a self() that, as its extends clause instantiates the supertype, returns another type than the pair's builder parameter - extends Fluent<String> where every generated setter returns self() as B. A link whose annotated ancestor declares a builder the extends clause cannot name is reported on the annotation instead, whether or not the link declares its own, as is a link the ancestor's builder is out of reach of - declared, or generated at the access the ancestor's @ClassBuilder(access) asks for - being private from another top-level class or package-private from another package, and a link whose extends clause names a generic ancestor without its type arguments. A concrete link is reported on its annotation, too, where the nearest self() it overrides is final on a compiled ancestor - one built without the processor, whose own builder nothing judged; a source ancestor's is reported on that ancestor's builder alone.

A constructor or static factory target merges into the builder its enclosing type declares, a static factory inside an interface included, so that builder is judged the same way. Its type parameters are measured against the ones the generated members are written in: a static factory's own, and the enclosing type's for a constructor. An annotated member the processor refuses - an instance or void method, or one beside an annotated type - merges nothing and is not judged.

On a shape the merge accepts, a field the author declares in the builder under a slot's name is also checked against the type the generated setters assign, type arguments included. A primitive field over its box is accepted, the setter assigning it under unboxing; a box over its primitive is reported, since an unset one reaches the primitive constructor parameter as null. A field written C-style, String tags[], is read with its brackets, and a varargs parameter's slot is the array it is. That is the field's declared type, except for a @Lazy field and a field whose kept initializer reads the instance - names this, super or an instance member, a getter or setter @Getter, @Setter or @Lazy generates among them - which the builder holds as a Supplier of it: so private String note; beside a @Lazy String note is reported, and private Supplier<String> note; is not. A @Collector slot whose initializer reads the instance is held in a plain java.util container of its elements - List, Set or Map - so private List<String> tags; holds an ArrayList<String> tags slot and private ArrayList<String> tags; is reported. A field under a slot's name declared final is reported whatever its type where one of the slot's generated setters that assigns it is appended - the author writing no method of its name and erased parameter types; where the author writes every one of them, nothing generated assigns the field. A singular add, put, remove or clear, and each bulk setter of an @Collector(append = true) slot, only add into or take from the container the field holds, and do not count. A @BuilderSeed has no setter and is never reported.

An author method of a generated setter's name and erased parameter types takes its place, and where that setter is the one from(T) and mutate() call - the one taking the slot's own type - they pass it the slot. Where the two parameters are distinct parameterisations of one generic type - items(List<Integer>) beside a List<String> slot, neither a wildcard nor one of the builder's type parameters - javac cannot pass it, and the method is reported on its name wherever either copy entry point is emitted.

A generated setter the merge appends overrides whatever the builder inherits under its name and erased parameter types, a parameter typed by one of the builder's type variables taking that variable's bound - value(T) meets an inherited value(Object). Where that inherited method is static or final, or returns void, a primitive or a type the builder is not assignable to, javac refuses the setter on the target's line; the builder's name is reported instead, naming the method and the supertype that declares it. The supertypes are the builder's superclasses up to and including java.lang.Object - a long wait slot's setter meets its final wait(long) - and its superinterfaces, whose static methods a class does not inherit. An inherited method of the same erasure whose parameter, as the builder's extends clause instantiates its supertype, is not the setter's type variable - value(T) beside a non-final value(Object), or value(T extends Number) beside value(Number) - is neither overridden nor overloaded, which javac refuses as a name clash, and is reported on the builder's name as one. A generic supertype's value(X) that the builder passes its T is the method value(T) overrides. An inherited method the setter can override, one returning the builder's own self type among them, and one taking other parameter types, are left alone.

On a constructor or static factory target, a @BuilderSeed parameter is appended to the declared builder as a final field, and only the author's constructors can assign it. A constructor that leaves it unassigned is reported, as is a builder declaring no constructor at all - javac refuses both - unless an instance initializer of the builder assigns it, which assigns it for every constructor. A constructor that may assign it where it is already assigned - after an instance initializer, after the this(..) call it delegates through, or twice itself, on two paths that meet or inside a loop - is reported too, the field being final, on the second assignment where javac reports one. A constructor an @AllArgsConstructor, @RequiredArgsConstructor or @NoArgsConstructor on the builder appends takes the builder's fields as they stand before the merge, so it leaves the seed unassigned; it is reported on the builder's name, where javac reports it, naming the appended constructor.

On a class or record target and on a constructor or static factory target, a builderConstructorAccess written on the annotation while the declared builder declares a constructor of its own is reported as a warning on that attribute: the author's constructor keeps the access it is written with. Where the declared builder declares no constructor, its implicit default takes the attribute's access instead. On a SuperBuilder chain role or an interface target the attribute reaches no builder at all, and a value other than the default written there is reported as a warning on the attribute too.

Shape rejections are reported at error level because the alternative is javac failing on a generated line. The message is the one the processor prints, rendered from the same decision, so the editor is red exactly where and for exactly the reason the build is.
