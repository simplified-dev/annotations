Reports a @ClassBuilder that generates nothing, because the target already declares a nested type named the same as the builder.

A class or record target merges the generated members into that declaration, the author winning every collision. Two positions do not merge and skip on it instead, and the only signal the build gives is a compiler note. Without this the entry points (builder(), from(T), mutate()) and the whole generated surface are simply absent from completion with nothing on the screen saying why - which reads as the annotation being broken rather than as the declaration having turned it off.

The message says which of the two the target is:

  • A target in a SuperBuilder chain - abstract, or extending an annotated class - aborts ahead of everything the pass would emit, including the retained-initializer providers, the copy constructor and the bootstraps.
  • A constructor or static factory target aborts the same way.

Reported at weak-warning severity because the code is correct: the author's own builder is what runs. What is worth knowing is that the generated half is off.
