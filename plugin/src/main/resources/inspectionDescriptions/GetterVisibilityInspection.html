Reviews the read accessors a class generates or hand-writes:
  • A field whose @Getter generates a public accessor that nothing outside the declaring class reads. Two fixes are offered, because they are different intents: @Getter(AccessLevel.NONE) deletes the accessor, @Getter(AccessLevel.PRIVATE) keeps it and stops publishing it.
  • The same accessor where every reader sits in the declaring package, or in a subclass - narrowed to PACKAGE or PROTECTED respectively.
  • A class declaring two or more zero-arg methods whose entire body is return this.field;, named as @Getter would mint them. One type-level annotation generates all of them, and the fix deletes only the methods it subsumes - every other field of the class is listed in the annotation's exclude, so the generated set is exactly the deleted one and no field the author never published gains an accessor.

The narrowing checks report at weak warning and will not be raised. A public accessor is part of what a module publishes, and this library ships to Maven Central - narrowing one is a downstream break that no amount of local evidence can rule out, since the search can only see this project. Treat the report as a review aid on a member nobody here reads, not as a cleanup sweep to run across a package.

Every narrowing fix writes a field-level @Getter, never the type-level one. The field-level override is the mechanism the annotation surface provides for exactly this, and it is what keeps an edit about one field from moving every sibling. A field-level annotation replaces the type's outright, so the narrowing carries the type-level style and name across with it - otherwise narrowing an accessor would rename it. The trivial-accessor fix is the one that writes a type-level annotation, because proposing one for the whole class is what it is for.

The trivial-accessor check reports at warning and its body test is exact: one statement, a return, over a field of the enclosing class, with the return type matching the field type. A null check, a defensive copy, a cast, a normalisation or a read of a different field is work the author wrote, and replacing it with a generated accessor would silently change behaviour. The fix additionally aborts, with an explanation rather than a silent no-op, when a method it would delete is reached through a method reference or declared by a supertype - neither of which a generated member can satisfy.
