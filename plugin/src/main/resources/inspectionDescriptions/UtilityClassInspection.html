Flags misuse of @UtilityClass:
  • An instance field or method under the default members = REQUIRE_STATIC. A utility class holds static members only, and the default policy reports the member rather than rewriting it. An Add 'static' fix is offered on the member.
  • constructorAccess = AccessLevel.NONE. Every class has a constructor, so there is no such thing as suppressing it - choose PRIVATE, PACKAGE, PROTECTED or PUBLIC.
  • A constructor the author declared. It keeps its body, so the throwing constructor is never synthesised and the class stays instantiable.
  • A target the annotation cannot apply to: a record, whose canonical constructor is its contract; an enum, already final with a private constructor; an interface or annotation type, which cannot be instantiated anyway; an abstract class, which would be made final; and a nested class that is not static all the way out, since an inner class carries a reference to its enclosing instance.
  • @ClassBuilder on the same type. One builds instances, the other declares the type uninstantiable.

Every check mirrors a diagnostic the annotation processor already emits. What the inspection adds is timing, position and a remedy: the processor can only report against the type and describe the fix in prose, while this underlines the offending member or attribute as it is typed and applies the fix in one keystroke.

The instance-member check is the reason the inspection exists. The default policy deliberately reports rather than rewrites, so no declaration silently changes meaning - but that means annotating an existing class turns each of its instance members into a compile error at once, with nothing to click on. Writing members = MAKE_STATIC asks for the rewrite instead and silences the check entirely.

The target-shape and attribute checks report at ERROR severity because the build cannot complete. A declared constructor reports at WARNING: the class still compiles, it just is not the utility class the annotation claims.
