Reports a hand-written equals and hashCode pair that @EqualsAndHashCode would generate, and offers to replace the two methods with the annotation.

The counterpart to Hand-written equals and hashCode read different state, which reports the pairs the annotation cannot adopt. Between them, a class carrying a hand-written pair gets an answer either way.

The match is exact, and that is the whole safety argument. Every statement of the equals has to be a recognised guard, the cast local, or the returned chain, and every term of that chain has to be the comparison the annotation emits for that member's declared type. A guard that reads the object's own state, a term this does not recognise, or a float compared with bare == where the annotation emits Float.compare - each means the generated relation could differ from the written one, and each drops the class from the report entirely rather than reporting it with a caveat.

hashCode is held to a weaker standard on purpose: it has to read the same members, and nothing more. A hash value is not part of any contract - only its consistency with equals is - so requiring the accumulator shape as well would reject almost every hand-written pair in order to protect a number nobody may depend on.

One difference is reported rather than rejected. Where the written equals compares an array member with Objects.equals, that is reference identity, and the annotation compares arrays by content. The finding says so in its own words and its fix is named (compares arrays by content), because adopting the annotation there changes equality - which is, in almost every case, the reason to adopt it.

The fix writes the attributes needed to reproduce what was written - identity where it is not the default, callSuper wherever there is a superclass to be explicit about, and exclude for any member the selection reaches that the written pair ignored. A member the selection does not reach on its own, such as a derived accessor or transient state, gets an @EqualsInclude marker written onto it; if there is nowhere to put that marker, the class is not reported at all.
