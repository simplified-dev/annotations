Flags misuse of @AllArgsConstructor, @RequiredArgsConstructor, @NoArgsConstructor and @BuilderArgsConstructor:
  • Applied to a record, interface or annotation type. A record's canonical constructor is its declared contract, and an interface has no constructor to generate.
  • access = AccessLevel.NONE, which is the absence of a member - leaving an annotation whose only job is to generate one with nothing to do. Delete the annotation instead.
  • @NoArgsConstructor on a class with a final field that has no initializer, which the generated constructor would leave unassigned. Give the field an initializer, or write force = true to accept the JVM zero value.
  • force = true where no final field is unassigned, making the attribute pure noise.
  • @BuilderArgsConstructor on a class carrying no @ClassBuilder. It names the field set of a generated builder, so without one it names nothing.
  • Two annotations that resolve to the same signature - most often @NoArgsConstructor beside a @RequiredArgsConstructor that selects no field at all.

Every check mirrors a diagnostic the annotation processor already emits. What this adds is timing and position: the processor can only report against the type, while the inspection underlines the offending attribute as it is typed.

Note that these annotations add a constructor rather than backing off when the class declares one of its own, so a hand-written constructor beside them is not reported. That is deliberate - an enum whose constants bind to a generated constructor relies on it.
