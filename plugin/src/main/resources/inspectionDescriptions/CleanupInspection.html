Flags a @Cleanup declaration the generated try-with-resources cannot be built from:
  • A declaration with no initializer, which holds no resource to close.
  • A declared type that is not AutoCloseable. The annotation expands to try (name) { ... }, and only an AutoCloseable may appear there.
  • A for or for-each variable. There is no remainder of an enclosing block for the resource to be closed at, so the annotation would do nothing at all.
  • A variable assigned again after its declaration. The existing-variable resource form requires it to be effectively final.
  • A variable declared by a try-with-resources, which already closes it.

These are checks the annotation processor is structurally unable to make. It runs before attribution, so it holds a syntax tree in which the local's declared type is a name and nothing more. Without the inspection a non-closeable type reaches the build as a type error on a try statement that appears in no source file, which is among the hardest diagnostics to connect back to the annotation that caused it.

A type whose close() happens to do nothing is not reported. Whether a close is inert is a property of the library that declared it rather than of the annotation, and deciding it means reading through an override chain to a body that need not be on the classpath. Every other check here stands for something that fails to compile.
