Rewrites a bare null argument to Optional.empty() on the dual setter an Optional field generates.

An Optional<T> field on a @ClassBuilder target gets x(T) alongside x(Optional<T>), so a caller holding a maybe-null T does not have to wrap it at the call site. The cost is that a literal x(null) is ambiguous: both parameter types accept null and neither is more specific, so the compiler cannot choose. Every other call shape resolves - including a null-valued variable, which carries a static type.

Optional.empty() is the only replacement offered because it is the only one worth writing. The raw overload wraps its argument with Optional.ofNullable, so a disambiguating cast such as x((String) null) stores precisely the same empty value while saying less about what was meant.

Available on any x(T) / x(Optional<T>) pair, not only on generated builders - a builder read from a compiled dependency carries no synthesis marker, and a hand-written pair has the same ambiguity for the same reason.
